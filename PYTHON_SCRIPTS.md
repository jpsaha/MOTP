# Python Scripts Guide

This guide describes the purpose of the seven Python scripts, their main inputs and outputs, and the order in which to use them.

Run commands from the repository root unless stated otherwise.

## 1. `_scripts/generate_contest_urls.py`

**Purpose:** Generate `_data/contest_urls.yml` from the contest question entries in `_data/past.yml`.

**Input**
- `_data/past.yml`

**Output**
- `_data/contest_urls.yml`

The script extracts the `qq`, `sol`, `src`, and `omc` fields for each question entry. A contest year with one question entry is assigned the `default` variant. If it has multiple entries, they are assigned letter variants (`a`, `b`, `c`, …). Contest years without question entries are skipped.

**When to run:** After editing the contest information in `_data/past.yml`, run this script before running `merge_contest_urls.py`.

```bash
python _scripts/generate_contest_urls.py
```

## 2. `_scripts/merge_contest_urls.py`

**Purpose:** Merge the contest PDF metadata generated by the previous script into the existing olympiad data.

**Inputs**
- `_data/olymp.yml`
- `_data/contest_urls.yml`

**Output**
- `_data/merged.yml`

The script matches contest/year/variant entries, adds the `qq`, `sol`, `src`, and `omc` metadata, and places the original problem list under `problems:`. It also reports variants for which metadata is matched or missing.

**When to run:** Run this after `generate_contest_urls.py`, and whenever the relevant source data changes.

```bash
python _scripts/merge_contest_urls.py
```

Check that the site's templates use the generated `merged.yml` data where intended.

## 3. `_scripts/liquid_include_tree.py`

**Purpose:** Inspect the Jekyll Liquid include structure.

The script examines templates in `_includes/` and `_layouts/`, as well as root-level HTML files, and displays the include tree. It recognizes `include` and `include_relative`, reports unresolved include names, and detects cycles.

**Inputs**
- Jekyll template files, especially those in `_includes/` and `_layouts/`

**Output**
- A diagnostic report printed in the terminal

**When to run:** Use it when investigating how templates include one another or when diagnosing unresolved includes or include cycles. It is a diagnostic tool, not a required step in the contest-data generation workflow.

```bash
python _scripts/liquid_include_tree.py
```

Use `-h` to inspect the script's available command-line options.

## 4. `acgnt.py`

**Purpose:** Generate topic pages from the CSV file containing problem information.

**Input**
- `_data/csv/no.csv`

**Output directories**
- `_geo/` — Geometry
- `_alg/` — Algebra
- `_comb/` — Combinatorics
- `_nt/` — Number Theory

The script reads the CSV rows and generates Markdown pages for supported subjects. Rows with unsupported subjects or an empty `pdf` field are skipped.

**When to run:** Run it after updating the source CSV or when the generated topic pages need to be recreated.

```bash
python acgnt.py
```

## 5. `check_pdf_links.py`

**Purpose:** Check whether local PDF links in the generated website point to existing PDF files.

**Inputs**
- Generated HTML under `_site/`
- PDF files under `assets/pdf/`

The script scans `_site/**/*.html`, extracts anchor links, and checks local links containing `/assets/pdf/...pdf` against the files under `assets/pdf/`. It reports missing PDF files.

**When to run:** Run this after building the Jekyll site. It checks the generated site, so `_site/` must already exist and be up to date.

```bash
bundle exec jekyll build
python check_pdf_links.py
```

## 6. `mopss.py`

**Purpose:** Generate dated Jekyll Markdown pages for MOPSS PDF files.

**Input**
- PDF files in `assets/pdf/MOPSS/`

**Output**
- Markdown pages in `_mopss/`

The script recognizes filenames in the `MOPSSYYMonDD.pdf` format and creates corresponding pages with date-based filenames, such as `yy<month><day>.md` using the lowercase month abbreviation. It prints the number of pages created.

**When to run:** Run it after adding or changing MOPSS PDFs, or when the generated pages need to be recreated.

```bash
python mopss.py
```

## 7. `pyq.py`

**Purpose:** Generate yearly question pages for RMO, INMO, and IOQM.

**Output directories**
- `_rmo/`
- `_inmo/`
- `_ioqm/`

The script uses its `CONFIG` list to define each contest's output folder, title, year range, and excluded years. It writes a Markdown page for each configured year that is not excluded. The current ranges and exclusions are defined directly in the script, so edit `CONFIG` when those ranges need to change.

**When to run:** Run it when the configured year ranges or exclusions change, or when the yearly pages need to be recreated.

```bash
python pyq.py
```

## Recommended workflow

For changes to the contest question metadata:

1. Edit `_data/past.yml`.
2. Run `python _scripts/generate_contest_urls.py`.
3. Update `_data/olymp.yml` if the olympiad problem data needs changes.
4. Run `python _scripts/merge_contest_urls.py`.
5. Build the Jekyll site.
6. Run `python check_pdf_links.py` to check for missing PDF files.

Use `_scripts/liquid_include_tree.py` when diagnosing template includes. Run `acgnt.py`, `mopss.py`, and `pyq.py` when their respective source data or generated pages need updating.

## Quick reference

| Script | Main purpose |
|---|---|
| `_scripts/generate_contest_urls.py` | Generate `_data/contest_urls.yml` from `_data/past.yml` |
| `_scripts/merge_contest_urls.py` | Merge contest PDF metadata into `_data/merged.yml` |
| `_scripts/liquid_include_tree.py` | Inspect Jekyll Liquid includes and diagnose unresolved includes/cycles |
| `acgnt.py` | Generate subject/topic pages from `_data/csv/no.csv` |
| `check_pdf_links.py` | Check generated HTML for links to missing local PDFs |
| `mopss.py` | Generate dated pages from MOPSS PDFs |
| `pyq.py` | Generate yearly RMO, INMO, and IOQM pages |

**Note:** The scripts that generate files may overwrite existing generated files. Review any relevant changes before committing them.
